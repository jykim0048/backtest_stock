# Live Trader — 장중 집행(분할 진입·청산·손절) 규칙·구현 기록

2026-10-18 명칭 변경: 구 `PLAN_VWAP.md` → **Live Trader**. 장중 시스템을 두 역할로 나눈다(§0).
코드 패키지 `swing/vwap/`·Railway 서비스 `swing-vwap`·키 `intraday/<date>` 는 이름을 그대로 둔다(운영 중 서비스 시작 명령 유지).

## 0. 역할 분리 — Live Trader(집행) vs Live PM(판단)
| | **Live Trader** (이 문서) | **Live PM** ([PLAN_PM.md](PLAN_PM.md)) |
|---|---|---|
| 한 줄 | 정해진 주문을 **어떻게** 체결할지 | 포트폴리오를 **무엇을** 바꿀지 |
| 입력 | swing 원장(그날 진입 주문·예약 청산·손절가), 허브 `/prices`, Live PM 지시 | Live Trader 가 공개한 장중 상태(가격·VWAP·체결·손절), 원장, 진입 근거(thesis) |
| 하는 일 | 시세 수신·VWAP 계산, 분할 체결(시가 10%·VWAP 60분할·5% 전량), **손절 감시·집행(하드 규칙)**, 지시 집행 | 트리거 감지, LLM 판단, RiskGate, 집행 **지시**만 발행, 평가 |
| LLM | 없음(규칙만) | 있음 |
| 쓰는 곳 | `intraday/<date>` — **유일한 작성자** | `livepm/<date>/…` (지시·호출 기록·평가). `intraday/<date>` 는 읽기만 |
| 원장 | 읽기만(16:30 `settle_day` 가 `intraday/<date>` 로 확정) | 읽기만 |
| 상태 | 구현·배포(swing-vwap, 2026-10-18) | M0 완료, M1~ 미구현 |

원칙:
- **손절은 Live Trader 가 단독으로 집행**한다. Live PM 이 멈추거나 틀려도 손절·분할 규칙은 그대로 돈다.
- Live PM 은 주문을 직접 내지 않는다. 지시(exit·trim·tighten_stop·flag_review)를 남기면 Live Trader 가 자기 규칙으로 집행한다.
- 원장 쓰기는 지금처럼 16:30 정산 한 곳뿐이다.

2026-10-18 사용자 결정(집행 규칙):
- **진입**: Long·Short 모두 trading_agent 진입가를 **상한**으로 두고, **VWAP 보다 유리한 가격에서 분할 매매**로 진입.
- **청산**: **장중 손절가 실시간 처리**.
- 2차(같은 날): 진입·청산(손절 포함) 모두 **10% 시가(손절은 도달가) + 나머지 VWAP 분할 + 기다리면 손해인 방향 5% 전량** — §2.
- **도입**: 바로 swing 원장에 반영. 처음 만든 별도 VWAP 단타 원장(1억)·신호 3종은 **제거**.

## 1. 구조
```
[장중 09:00~15:35] swing-vwap 서비스 (python -m swing.vwap)
   swing 원장(ledger) 읽기만 ── 그날 유효 진입 주문 + 손절 감시 대상 포지션
   허브 /prices 15초 폴링 → 종목별 VWAP → 분할 체결 · 손절 판정
   → intraday/<date> 에 기록(원장은 고치지 않음)
[16:30] swing-cron run_day → engine.settle_day(L, D, bars, intraday=intraday/<date>)
   감시한 주문 = 분할 체결 기록으로 체결 / 감시한 포지션 = 장중 손절 기록으로 청산
   실행기가 안 돈 날·감시 밖 = 종전 일봉 규칙(자동 폴백)
```
원장 쓰기는 지금처럼 하루 한 번(16:30)뿐이라 동시 쓰기 충돌이 없다. 끄기: `SWING_INTRADAY=0`(정산이 기록을 무시).

## 2. 분할 방식 — 진입·청산 공통 (2026-10-18 2차 결정)
사용자 결정: "모든 진입·청산(손절 포함)은 주문수량의 10% 를 시가에 체결하고 나머지는 VWAP 로직", 시가 10% 는 진입가 상한 무시,
"시가 체결 가격 대비 ±5% 이상 강한 상승/하락 시 VWAP 로직 무시하고 전량 체결" → 같은 날 "기다리면 손해인 방향으로만" 좁힘.

| # | 단계 | 진입(Long, Short 대칭) | 청산(Long 매도, Short 환매 대칭) |
|---|---|---|---|
| S1 | 첫 분할 = 수량의 10%(`OPEN_PCT`) | **시가** 체결, 진입가 상한 무시. 단 시가가 손절가 너머면 생략하고 그 수량을 다음 분할에 합침 | 예약 청산(재판별·최대 보유·신호 트리거) = **시가**, 손절 = **손절 도달 가격**(시가부터 넘었으면 시가) |
| S2 | 기준가 | S1 체결가(생략 시 시가) | S1 체결가 |
| S3 | 나머지 90% 를 **60분할**(`TRANCHES`, 2026-10-18 3 → 60, 나머지 주식은 앞쪽 분할에 1주씩, 60주 미만이면 1주씩), VWAP 분할끼리 **5분** 간격(`MIN_GAP_MIN`, 2026-10-18 20 → 5), 09:05~15:19 | 가격 ≤ 진입가(상한) 그리고 ≤ VWAP 그리고 > 손절가 | 가격 ≥ VWAP |
| S4 | 기준가 대비 **기다리면 손해인 방향으로 5%**(`FORCE_MOVE`) 이상 → VWAP·상한 무시하고 남은 수량 전량. 반대 방향이면 VWAP 분할 계속(2026-10-18 방향 제한) | Long +5% 상승 · Short −5% 하락, 손절가 안쪽일 때만 | Long 매도 −5% 하락 · Short 환매 +5% 상승 |
| S5 | 그날 못 채운 수량 | 기존 부분 진입 잔여분 다음 영업일 추가 주문(같은 상한). 한 주도 못 사면 "미도달(VWAP…)" → 미도달 재주문 | 다음 영업일 계속(`sellPending` 유지 — 실행기가 없으면 엔진이 시가 청산) |

- 규칙값은 `swing/vwap/config.py` 상수(환경변수로 덮어쓰지 않음, 2026-10-18 사용자 결정) — 바꿀 땐 코드와 이 문서를 함께 고친다.
- 체결가 기록은 `intraday/<date>` 의 `fills[{ts, qty, price, mode}]`, mode = open·vwap·force·stop·stop_gap.
- VWAP = 누적거래대금 ÷ 누적거래량(허브 `/prices` 의 `value`, 2026-10-18 배포 확인).

## 3. 장중 손절 감지
| # | 규칙 |
|---|---|
| V7 | 감시 대상 = 보유 포지션(예약 청산 중인 것은 손절 감시 대신 S1~S5 분할 청산, 체결일 손절 재판별 대기는 제외) + 그날 분할 체결분 |
| V8 | 판정: 현재가가 손절 넘음 **또는** 당일 저가(Short 고가)가 직전 틱 이후 손절 너머로 새로 갱신 → 손절 청산 시작(S1 = 손절가) |
| V9 | 처음 본 순간(기동 지연·재시작) 이미 당일 저가가 손절 너머면: 시가가 손절 너머였으면 시가(stop_gap), 아니면 손절가 |
| V10 | 분할 진입 중 손절되면 남은 진입 분할 취소 → 체결분은 손절 청산(S1~S5). 본 포지션이 손절되면 그 종목 잔여분 추가 주문 분할도 취소 |

정산 반영(`engine.settle_day(…, intraday=)`, `engine._apply_exit`):
- 청산 기록은 체결 합 수량을 평균가로 **일부 청산**(`_close_position(qty=)` — 숏 진입세·대차수수료는 수량 비율 배분)하고, 남으면 `sellPending`
  (사유 "분할 청산 잔여 N주") 로 다음 날 계속. 예약 청산 = ① 단계, stop_gap = ② 단계, 손절 = ④ 단계.
- 체결일 손절: 실행기가 체결 후 손절을 관측했으면 그날 바로 손절 청산 시작(체결일 재판별 규칙보다 우선).
- 세션 완주(마지막 틱 15:30 이후)에 손절 기록이 없으면 그날 일봉 손절 판정 생략, 미완주면 기록 없는 포지션은 일봉 규칙으로 폴백.
  목표가 도달 재판별은 항상 일봉 판정(변경 없음).

### 60분할·5분 간격
체결 가능 시간 09:05~15:19(374분)에 5분 간격이면 하루 VWAP 분할은 최대 74번 → 조건이 자주 맞는 날은 60분할을 그날 끝낼 수 있다.
조건(VWAP 보다 유리한 가격)이 드문 날은 여전히 남은 분할이 진입 = 잔여분 추가 주문, 청산 = 다음 날 계속으로 넘어간다.

### 주의(합성 재생에서 관찰, 2026-10-18)
- **손절 후 계속 밀리는 종목**: 10% 만 손절가에 팔리고, 가격이 VWAP 아래에 머물면 VWAP 분할이 나오지 않아 기준가 −5% 에서 나머지를
  전량 매도한다 → 손절가보다 최대 약 5% 더 손실. 반대로 반등하면 VWAP 위에서 더 좋은 가격에 판다.
- (해소) 진입 중 하락에도 전량 매수하던 문제는 S4 방향 제한으로 없앴다 — 하락 중 Long 진입은 VWAP 분할로만 채운다.

## 5. Live PM 지시 인터페이스 (제안 — 미구현)
Live PM 이 생기면 Live Trader 는 매 폴링마다 `livepm/<date>/instructions`(추가만 하는 목록)를 읽어 새 지시를 집행하고,
결과를 `intraday/<date>.instructions[지시 id]` 에 남긴다. Live PM 은 이 결과를 읽어 다음 판단에 쓴다.

| 지시 | 내용 | Live Trader 집행(제안) |
|---|---|---|
| `exit` | 포지션 전량 청산 | 청산 슬라이스 생성(trigger=`livepm`) — 첫 10% 즉시(현재가), 나머지 VWAP 분할·5% 전량. 정산 사유 `livepm_exit` |
| `trim` | 일부 청산(pct) | 같은 방식, 수량 = 보유 × pct |
| `tighten_stop` | 손절가를 유리한 쪽으로만 이동 | 그 시각부터 새 손절가로 감시. 정산 때 원장 손절가 갱신(그날 일봉 손절 판정은 기존 손절가) |
| `flag_review` | 장 마감 후 trading_agent 재판별 | `intraday/<date>` 에 표시 → 정산 후 run_day 가 재판별 대상에 추가 |

정할 것(사용자): exit·trim 을 분할 집행할지 즉시 전량 집행할지, Live PM 을 swing-vwap 프로세스 안에서 돌릴지 별도 서비스로 둘지,
shadow 기간을 둘지. 결정되면 이 절과 PLAN_PM.md 를 함께 고친다.

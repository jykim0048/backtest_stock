메인 대시보드(backtest_stock)의 '주가 영향 분해 3D'와 같은 것을 swing paper 판단 팝업에 넣는다.

## 정해진 것 (2026-11-11 사용자 결정)

- 성과 기여도(Long·Short PF 탭)에는 3D 를 넣지 않는다.
- 판단 팝업의 기존 형식은 그대로 둔다. **트레이딩 히스토리 카드 위** 맨 윗줄에 3D 카드를 추가한다.
- (2026-11-12) 맨 윗줄 = 왼쪽 PM 등급~비중 카드 3×2(+ 그 아래 PM 요약) · 오른쪽 당일 등락 요인 분해 카드. 760px 미만은 위아래로.
- 내용은 메인과 같이 당일 등락률 → 항목 → 요인 분해.

## 화면

```
[팝업 제목]
┌ 왼쪽 ─────────────────────────────┐ ┌ 오른쪽 ─────────────────────────────┐
│ [PM 등급] [Trader]   [진입가 리밋] │ │ 당일 등락 요인 분해 · 기준 등락률 · 추정 │  ← 새 카드(접기 가능)

└───────────────────────────────────┘ └──────────────────────────────────────┘
[트레이딩 히스토리]                                       ← 그대로
[종합 리포트 I~V · 부록]                                  ← 그대로
```

- 항목 = 애널리스트 5역할: 기술적 분석(market)·심리(sentiment)·뉴스·공시(news)·펀더멘털(fundamentals)·수급(flow).
  요인 방향만으로 등락률이 설명되지 않으면 '기타·시장' 구가 하나 더 생긴다(메인과 같음).
- 공 크기 = |%p|, 빨강 = 주가를 올린 요인, 파랑 = 내린 요인, 회색 = 중립.
  색은 **주가 방향** 기준이다 — Short 포지션에는 반대로 작용한다는 한 줄을 카드 아래에 적는다.
- 항목 구·요인 공을 누르면 아래 종합 리포트의 그 항목(I-1~I-5)이 펼쳐진다. 요인을 누르면 근거 한 줄이 칩으로 뜬다.
- 요인 데이터가 없는 판단(기능 켜기 전의 판단·판단 실패)이나 WebGL 이 안 되는 기기에서는 카드만 숨긴다.
- 히스토리 카드가 없는 종목(미체결 등)도 요인만 있으면 같은 자리에 카드가 나온다.

## 데이터 — 요인은 어디서 나오나

메인은 분석 호출 하나가 모든 원자료를 보고 요인을 낸다. swing 은 역할이 14개로 나뉘어 있어 선택지가 셋이다.

| 방법 | LLM 호출 | 장단 | 채택 |
|---|---|---|---|
| A. 애널리스트 5명이 각자 자기 항목의 요인을 같이 낸다(`{markdown, factors}`) | +0 | 원자료를 직접 본 역할이 낸다 · 항목마다 요인이 고르게 나온다(메인은 평균 6개로 적었음) · 역할끼리 강도 눈금이 다를 수 있다 | **채택** |
| B. Research Manager 한 번에 전 항목 요인 | +0 | 눈금이 일관되지만 RM 은 토론 전문만 본다(원자료·리포트 원문 없음) | 대안 |
| C. 요인 추출 전용 호출 추가 | 종목당 +1 | 가장 충실하지만 이미 lite 한도(500/일)를 넘는 상태 | 보류 |

- kit 역할 파일은 건드리지 않는다. `pipeline.py` 의 애널리스트 호출 5개만 스키마를 넓히고, 요구는 user 프롬프트 끝에 붙인다:
  당일 등락(종가·전일 종가·등락률 — `01_price.json` 에서 코드가 계산해 넣음)에 영향을 준 요인 1~4개,
  방향 up/down/neutral, 강도 "1"~"5", 근거 1문장, 입력 자료에 있는 사실만, %p 는 쓰지 않는다(코드가 계산).
- **실패해도 판단은 그대로**: `factors` 가 없거나 형식이 틀리면 버린다. `markdown` 을 꺼내는 경로는 바꾸지 않는다.
- `swing/agent/price_factors.py`(새 파일): 메인 `analysis/price_factors.py` 의 `clean`·`attribute`·`build` 를 옮긴다
  (swing 은 main 과 병합 금지 → 복사. 항목 이름만 다름). 판단 문서에 `priceFactors = {basis, items, byCat}` 로 저장.
- 재판별도 같은 파이프라인이라 보유 종목은 재판별 때마다 요인이 새로 생긴다.

## 기준 등락률 — '당일'

- 저장할 때: 판단일 등락률(정산은 장 마감 뒤라 그날 종가 기준).
- 볼 때: `/api/swing/decision` 이 같은 회차의 **가장 최근 판단**(진입 또는 마지막 재판별)의 요인을 고르고,
  실시간 시세(`history.live_prices` 의 price·prevClose)가 있으면 `today = {price, prevClose, ratePct, ts}` 를 같이 준다.
  대시보드는 `today` 가 있으면 그 등락률로 다시 나눈다(메인과 같은 식의 JS 판) — 요인은 전날 저녁 판단의 것이고
  숫자만 오늘 등락에 맞춘다는 뜻이므로, 카드에 '요인 11/10 재판별 · 등락률 11/11 15:34' 처럼 둘 다 적는다.
- 요인이 이 팝업의 문서가 아니라 재판별에서 왔으면, 항목을 눌렀을 때 그 재판별 원문을 연다(기존 '원문 ›' 이동과 같은 방식).

## 순서와 위험

1. 파이썬(요인 생성·저장·API) + 테스트 → 2. 대시보드 카드 → 3. 장 마감 후 푸시 → 4. 그날 정산에서 요인이 붙는지 확인.
- 첫 정산 전까지는 어떤 종목에도 카드가 안 뜬다(메인에서 겪은 것과 같음). 소급 생성은 호출이 들어가므로 하지 않는다.
- 애널리스트 응답이 길어진다 — 잘림이 없는지(max_tokens 4096), 분당 토큰 한도에 걸리지 않는지 첫 정산에서 본다.
  호출 수는 그대로라 하루 호출 한도(lite 500/일)에는 영향이 없다.
- 푸시 규칙: `pipeline.py` 를 만드는 곳은 정산(`run_daily.make_agent`)뿐이지만 `agent_iface.py` 는 여러 곳이 쓰고,
  Railway 감시 경로는 UI 설정이라 레포에서 확인할 수 없다 → **장 마감 후, 정산(17:05~) 시작 전**에 올린다.

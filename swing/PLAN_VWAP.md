# swing 장중 VWAP 실행 — 분할 진입·장중 손절 규칙·구현 기록

2026-10-18 사용자 결정:
- **진입**: Long·Short 모두 trading_agent 진입가를 **상한**으로 두고, **VWAP 보다 유리한 가격에서 분할 매매**로 진입.
- **청산**: **장중 손절가 실시간 처리**(예약 매도·목표 재판별 등 나머지 청산 규칙은 그대로).
- **도입**: 바로 swing 원장에 반영. 처음 만든 별도 VWAP 단타 원장(1억)·신호 3종은 **제거**.
- Live PM(PLAN_PM.md)은 중단 상태. 시세 공급 `swing/intraday/feed.py` 는 Live PM M1 에서 재사용.

## 1. 구조
```
[장중 09:00~15:35] swing-vwap 서비스 (python -m swing.vwap)
   swing 원장(ledger) 읽기만 ── 그날 유효 진입 주문 + 손절 감시 대상 포지션
   허브 /prices 15초 폴링 → 종목별 VWAP → 분할 체결 · 손절 판정
   → intraday/<date> 에 기록(원장은 고치지 않음)
[16:30] swing-cron run_day → engine.settle_day(L, D, bars, intraday=intraday/<date>)
   감시한 주문 = 분할 체결 기록으로 체결 / 감시한 포지션 = 장중 손절 기록으로 청산
   실행기가 안 돈 날·감시 밖 = 종전 일봉 규칙(자동 폴백)
```
원장 쓰기는 지금처럼 하루 한 번(16:30)뿐이라 동시 쓰기 충돌이 없다. 끄기: `SWING_INTRADAY=0`(정산이 기록을 무시).

## 2. 분할 진입 (R-V1~V6)
| # | 규칙 | 기본값(노브) |
|---|---|---|
| V1 | 대상 = 그날 유효한 진입 주문 전부(신규·미도달 재주문·잔여분 추가 주문). 이미 보유한 종목의 신규 주문은 제외(엔진도 '이미 보유'로 건너뜀) | — |
| V2 | 계획 수량을 **3분할**(나머지는 마지막 분할에) | `VWAP_TRANCHES`=3 |
| V3 | 체결 조건 — Long: 가격 ≤ 진입가(상한) **그리고** 가격 ≤ VWAP **그리고** 가격 > 손절가. Short: 가격 ≥ 진입가(하한) 그리고 가격 ≥ VWAP 그리고 가격 < 손절가 | — |
| V4 | 조건을 만족한 폴링 틱의 가격으로 한 분할 체결, 분할 사이 **20분** 이상 | `VWAP_MIN_GAP_MIN`=20 |
| V5 | 체결 시간 09:05 ~ 15:19(동시호가 직후·종가 단일가 제외) | `VWAP_ENTRY_START`·`VWAP_ENTRY_END` |
| V6 | 정산: 수량 = 체결 합, 진입가(포지션) = **체결 평균가**. 일부만 체결되면 잔여분은 기존 '부분 진입 잔여분 다음 영업일 추가 주문'(같은 진입가 상한) 경로로 넘어간다. 한 분할도 못 하면 "미도달(VWAP 분할…)"로 취소 → 기존 미도달 재주문 규칙 적용 | — |

- 현금·담보 부족 처리(부분 진입·손실 종목 청산)는 체결 합 수량에 그대로 적용한다(정산 시점).
- VWAP = 누적거래대금 ÷ 누적거래량(허브 `/prices` 의 `value`, KIS 당일 누적 — 정확값). 허브가 `value` 를 아직 주지 않으면
  폴링 구간 근사(Σ가격×Δ거래량, 서비스 시작 이후)로 대체하고 `source="approx"` 로 기록한다.

## 3. 장중 손절 (R-V7~V10)
| # | 규칙 |
|---|---|
| V7 | 감시 대상 = 보유 포지션 중 시가 청산 예약(엔진 ①)·체결일 손절 재판별 대기(그날 손절 유예)를 뺀 전부 + 그날 분할 체결분 |
| V8 | 판정: 현재가가 손절 넘음 **또는** 당일 저가(Short 고가)가 직전 틱 이후 손절 너머로 새로 갱신 → **손절가** 청산 |
| V9 | 처음 본 순간(기동 지연·재시작) 이미 당일 저가가 손절 너머면: 시가가 손절 너머였으면 **시가**(stop_gap), 아니면 손절가 |
| V10 | 분할 체결 후 손절되면 남은 분할 취소. 본 포지션이 손절되면 그 종목의 잔여분 추가 주문 분할도 취소 |

정산 반영:
- stop_gap → 엔진 ② 단계(시가 청산과 같은 자리), 나머지 손절 → ④ 단계에서 기록 가격으로 청산(사유 `stop`, 메모 "장중 손절 HH:MM").
- **체결일 손절**: 지금은 체결일 손절가 도달 시 다음 날 재판별(`SWING_FILL_DAY_STOP=review`)인데, 장중 실행기가 체결 후
  손절을 관측했으면 순서를 알기 때문에 **그날 손절가로 바로 청산**한다(실행기 기록이 우선).
- 세션을 완주(마지막 틱 15:30 이후)했고 손절 기록이 없으면 그날 일봉 손절 판정은 생략한다. 완주하지 못했으면 기록이 없는 포지션은
  일봉 규칙으로 폴백한다(손절 누락 방지). 목표가 도달 재판별은 항상 일봉으로 판정(변경 없음).

## 4. 구성
```
swing/intraday/feed.py   Tick · PollingFeed(/prices) · ReplayFeed
swing/vwap/state.py      종목별 VWAP·σ·1분봉·당일 고저 갱신 감지
swing/vwap/executor.py   분할 진입·장중 손절 판정 → intraday/<date>
swing/vwap/__main__.py   swing-vwap 서비스 루프 · --replay(검증)
swing/engine.py          settle_day(…, intraday=) — 기록 반영·폴백
swing/daily.py           run_day 가 intraday/<date> 를 읽어 넘김, run 로그 intraday 요약
swing/server.py          GET /api/swing/intraday[?date=]
```
저장 키: `intraday/<date>`(실행기 기록), `intraday/<date>/ticks/<code>`(15초 틱, 재생용 — 백업 export 제외).

## 5. 남은 작업
- 허브 `/prices` 에 누적거래대금 `value` 추가분 푸시 + vi_limit 재빌드(로컬 변경만 있음).
- Railway 서비스 `swing-vwap` 생성 — 사용자 작업: 같은 레포·`swing_paper` 브랜치, config `swing/railway.vwap.json`
  (상시 실행, 장 시간 외 대기), 변수 `DATABASE_URL`=`${{Postgres.DATABASE_URL}}`·`FLOW_API_BASE`.
- 대시보드: 보유·진입 내역에 분할 체결(`vwapFills`)·장중 손절 시각 표시.
- 몇 주 운용 후 분할 수·간격, 미체결 비율(VWAP 조건 때문에 놓친 진입)과 체결가 개선폭(평균가 vs 진입가) 점검.

## 2. R1·R2·R4 를 함께 걸면 (산수)
현금 담보 Short 는 진입 금액만큼 현금이 담보로 묶인다. 그래서 **Long + 담보로 묶인 현금 + 남는 현금 = 평가액**.
- R2 의 "현금"은 **담보로 묶이지 않은 남는 현금** 기준으로 본다(원장 현금 = 이미 담보분을 뺀 값). ← 이 해석이 맞는지 확인 필요(7절 ①).
- 대용 Short 한도 = Long × 대용가 70% ÷ 증거금률 50% = Long × 140% — 담보가 한도를 막지 않는다(종전 100% 가정에선 막혔음).
- 성립하는 조합 예:
  | Long | Short(현금 담보 + 대용) | 남는 현금 | 순노출 | 총노출 |
  |---|---|---|---|---|
  | 52.5% | 37.5% (37.5 + 0) | 10% | +15% | 90% |
  | 55% | 45% (45 + 0) | 0% | +10% | 100% |
  | 58.6%(현재) | 43.6% (39.5 + 4.1) | 0% | +15% | 102% |
  | 70% | 60% (30 + 30) | 0% | +10% | 130% |
- **지금 장부 기준: Long 은 그대로 두고 Short 를 20.8% → 약 44~50%로(2배 남짓) 늘리면 두 한도가 맞는다.** 총노출은 79% → 100% 안팎.
  (처음 계획서의 "총노출 165~210%"는 대용 100% 가정에서 나온 값 — R4 로 크게 낮아졌다.)
- 세부(구현 때 확정): Long 매수도 같은 현금을 쓴다 → **그날 Long 주문 필요 금액을 뺀 현금부터 Short 담보로** 쓰는 순서를 제안.
  기존 Short(대용 방식 21종목)는 진입 당시 방식 그대로 정산하되, 한도 계산은 장부 전체 기준으로 한다.

## 3. R3 종목당 상한
- `MAX_WEIGHT` 단일값(10%) → `max_weight(code)`: 코스피 시총 1·2위 10%, 나머지 5%.
  시총 순위는 그날 유니버스 산출물의 시가총액(DB증권)으로 매일 판정(현재 삼성전자·SK하이닉스), 유니버스가 없으면 직전 값 유지.
- 적용 지점: 신규 주문 비중(PM·Trader 비중 상한), 비중 채우기(topup), Live PM 추가 지시. 스위칭 D(승자 보호 — PM 비중 초과분 매도)와 충돌 없음.
- 기존 보유가 상한을 넘는 경우(현재 최대 7.7%): 강제 축소하지 않고 추가 매수만 막는다. 가격 상승으로 넘은 것도 같은 처리.
- 산수: 상한 5%면 Long 55~60%는 **최소 11~12종목**(꽉 채웠을 때), Short 45%는 **최소 9종목**. 지금 종목 수(18·21)는 충분 — 모자란 건 종목당 체결 비중(Short 평균 1%).

## 5. 설계 — "노출 관리" 계층
- `swing/exposure.py`(신규, 순수 함수): 원장 + 대기 주문 → Long%·Short%·순노출·남는 현금%·섹터별 순비중·종목별 상한 여유·밴드 대비 여유.
- 설정: `NET_MAX=+0.15` `NET_MIN=−0.10` `CASH_MAX=0.10` `NET_BUFFER=0.02`(밴드 안쪽 2%p 에서 미리 조절) `SECTOR_NET_MAX=0.10`(6절)
  `EXPOSURE_MODE = off | monitor | soft`. 순노출은 금액 기준(베타 미조정).
- **정산(17:05)**: ① R3 상한 적용 ② 방향 게이트 — 진입 우선순위(PM 등급 → 비중) 앞에 "밴드로 되돌리는 방향 우선" ③ 비중 확대
  ④ (선택) 지수 레그 ⑤ run 문서에 `exposure`{before, plan, notes} 기록.
- **장중(Live Trader)**: 체결 직전 검사 — 이 체결로 순노출이 밴드(완충 포함)를 넘으면 그 슬라이스를 미루고 반대편 체결을 기다린다.
  청산(손절·목표)으로 벗어나는 건 막지 않는다(위험 축소 우선) → 다음 정산에서 되맞춤. `swing/vwap/` 변경이라 장중 푸시 금지.
- **담보(R4)**: `SHORT_COLLATERAL=cash_first`(신규) — 체결 시 남는 현금이 진입 금액 이상이면 현금 담보, 아니면 대용. `SHORT_MARGIN=0.5`.
- **가격 변동 이탈**: 완충 안이면 유지, 밴드를 넘으면 다음 정산의 신규 주문으로만 조정(보유 강제 축소 없음 — soft).
- **대시보드**: 계좌 현황에 순노출 밴드 게이지·남는 현금 한도, 섹터 표에 ±10% 초과 표시, 종목 표에 상한 대비 비중.

## 6. 섹터별 순노출 관리 — 의견
제안: 섹터 순노출이 ±10%를 넘으면 반대 방향 종목을 찾아 포지션을 잡아 10% 안으로 되돌린다.

**좋은 점**
- 총 순노출만 보면 "IT +14% · 전기전자 −11%" 처럼 섹터끼리 상쇄된 쏠림이 안 보인다. 섹터 한도는 이 쏠림을 직접 막는다.
- 같은 섹터 안에서 Long·Short 를 맞추면 섹터 등락은 상쇄되고 종목 선택 차이만 남는다 — 롱숏 본래 목적에 맞다.
- 유니버스가 이미 업종별 상방·하방 순위를 매일 내므로 "그 섹터의 반대 방향 후보"는 새 데이터 없이 나온다.

**걸리는 점**
1. **전략의 신호와 정면으로 부딪친다.** Long 후보는 강한 섹터(동반강세·수급유입), Short 후보는 약한 섹터(동반약세·수급이탈)에서 나온다.
   강한 섹터에서 Short 를 "찾아서 반드시" 잡으면 섹터 신호를 거스르는 포지션이 되고 기대 수익이 낮다. 섹터 로테이션에서 나오던 수익도 줄어든다.
2. **강제 진입은 판단 게이트를 무너뜨린다.** 지금은 PM 이 Sell·Underweight 를 줘야 Short 에 들어간다. 한도를 맞추려고 등급 미달 종목에 들어가면 품질이 떨어진다.
3. **Short 는 주식선물 상장 종목만** 가능 — 섹터에 따라 후보가 없거나 적을 수 있어 섹터 안에서 못 맞추는 경우가 생긴다(섹터별 가능 종목 수는 P0 에서 집계).
4. **섹터 한도만으로 총노출이 묶이지 않는다.** 15개 섹터가 각각 +8%면 총 +120%다. 총 순노출 밴드(R1)는 그대로 필요 — 섹터 한도는 보조 규칙.
5. 반대 방향 탐색은 하루 판단 수(42건)를 쓴다. R3(종목 5%)와 겹치면 한 섹터에서 한쪽 2종목만 꽉 채워도 한도에 닿아 발동이 잦다.

**권하는 형태 — "브레이크 먼저, 탐색은 우선 검토, 강제 진입 없음"**
- **1단 브레이크**: 섹터 순노출이 ±10%에 닿으면 그 섹터의 같은 방향 신규·비중 채우기를 멈춘다. 나쁜 포지션을 만들지 않고 비용도 없다.
- **2단 우선 검토**: 그 섹터의 반대 방향 후보(유니버스 하방/상방 순위, 주식선물 종목)를 판단 순서 앞에 둔다. **PM 등급을 통과할 때만** 진입하고
  크기는 "±10%로 되돌리는 데 필요한 금액"과 R3 상한 중 작은 쪽.
- **3단 잔여**: 섹터 안에서 못 맞춘 초과분은 그대로 두되 총 순노출 밴드에서 다른 섹터의 반대 방향 진입(또는 지수 레그)으로 흡수.
- 문턱은 발동 ±10% / 해제 ±8%로 간격을 둔다(오르내리며 매매가 반복되는 것 방지). 종가 기준 판정.
- P0 에서 먼저 확인: 과거에 섹터 ±10% 초과가 얼마나 잦았는지, 그때 같은 섹터에 통과 가능한 반대 방향 후보가 있었는지, 반대 방향 포지션의 실제 성과.

## 7. 확인·결정이 필요한 것
1. **R2 의 "현금"** = 담보로 묶이지 않은 남는 현금으로 보는 해석이 맞는지(2절).
2. **현금 담보와 Long 매수의 순서** — 그날 Long 주문 필요 금액을 먼저 떼고 남는 현금을 Short 담보로(제안) vs Short 담보 먼저.
3. **섹터 관리** — 6절의 "브레이크 + 우선 검토(강제 진입 없음)"로 갈지, 반대 방향 진입을 의무로 할지.
4. **지수 헤지 레그**를 허용할지(종목만으로 밴드를 못 맞추는 날의 처리).
5. ~~전환 속도~~ → **결정(2026-11-10): 주당 10%p 씩 단계적으로**(0절 "단계 한도").
6. 한도 판정은 **종가(정산) 기준**, 장중은 완충(±2%p)만 — 로 충분한지.

## 8. 단계
| 단계 | 내용 | 매매 영향 | 푸시 |
|---|---|---|---|
| **P0 진단** | 과거 일별 Long·Short·순노출·현금·섹터 순비중 재구성 / Short 체결률 원인 분해 / 규칙 적용 시뮬(필요했을 조정량, 섹터 초과 빈도·반대 후보 유무) | 없음 | — |
| **P1 표시** | `exposure.py` + 대시보드 게이지·경고(`monitor`) | 없음 | 장중 가능 |
| **P2 상한·게이트** | R3 종목 상한, 방향 게이트, 섹터 브레이크(`soft`) | 있음 | 15:40~17:00 |
| **P3 담보·채움** | R4 담보(cash_first·증거금률 50%), 비중 확대, 섹터 반대 방향 우선 검토 | 큼 | 15:40~17:00 |
| **P4 장중** | Live Trader 체결 직전 검사, (결정 시) 지수 레그 | 큼 | 장 마감 후만 |
- 각 단계는 `EXPOSURE_MODE`·개별 설정으로 켜고 끈다. 테스트: 순수 함수 단위 테스트 + 과거 원장 재생 시뮬(P0 도구를 회귀 테스트로 유지).

## 9. 위험·주의
- Short 가 2배 이상으로 늘어난다 — 숏 스퀴즈·상한가 위험, 대차료·거래세가 그만큼 증가.
- 순노출이 +38% → +15% 이하로 줄면 **시장 방향 손익이 크게 줄고** 성과가 Long·Short 종목 선택 차이에 더 의존한다.
- R5(첫날 손절가 도달 후에도 진입 계속)는 체결률을 올리지만, 논리가 흔들린 날에 수량을 다 채우게 된다 — D+1 재판별에서 매도 판정이 나오면 손실 규모도 커진다.
- Short 는 주식선물 상장 종목만 → 후보 풀이 좁다. 섹터 안 헤지가 안 되는 섹터가 있다.
- LLM 판단 한도(하루 42건)는 그대로 — 반대 방향 탐색은 이 안에서 자리를 쓴다.
- 모의투자의 Short 체결 가정(지정가·VWAP)과 실제 주식선물 유동성 차이 — 비중이 클수록 괴리.
